## Единый лабораторный профиль

- [x] Desktop: viewport 1440×900, CPU slowdown ×4, сеть 10 Мбит/с, RTT 40 мс.
- [x] Mobile: viewport 390×844, CPU slowdown ×4, сеть 1,6 Мбит/с, RTT 150 мс.
- [x] Каждый сценарий проверяется отдельно с холодным и тёплым кешем.
- [x] Итог для времени — медиана минимум из трёх production-прогонов.

Профиль зафиксирован для будущих лабораторных прогонов. В этом этапе browser QA не выполнялся: по правилам проекта он запускается только после явного запроса.

## Цель

Сделать первый отклик сайта визуально мгновенным, а тяжёлую графику загружать поэтапно, не меняя принятую композицию и характер движения.

`0,2 с` используем как цель для первого ответа интерфейса или появления фирменного экрана при хорошем соединении, а не как обещание полной готовности WebGL на любом устройстве.

## Целевые лимиты

- [ ] Первый визуальный отклик: **до 0,2–0,3 с** на тёплом соединении с близким CDN.
- [ ] FCP: **до 1,0 с desktop**, **до 1,5 с mobile** в согласованном тестовом профиле.
- [ ] LCP: **до 1,8 с desktop**, **до 2,5 с mobile**.
- [ ] INP: **до 200 мс**.
- [ ] CLS: **до 0,05**.
- [ ] Критический JavaScript: **не более 180 КБ gzip**.
- [ ] Критическая передача до первого содержательного кадра: **не более 300 КБ**, без отложенной WebGL-сцены.
- [ ] В стартовой цепочке нет чанка крупнее **500 КБ minified**.
- [ ] HDR, видео и медиа не конкурируют с HTML, критическим CSS и шрифтом.
- [ ] Повторный визит использует долгий кеш и не скачивает неизменившиеся ресурсы заново.

Цифры принимаются только после проверки на реальном размещении. Локальный dev-сервер не является доказательством скорости.

## Ограничения, которые сохраняем

- [ ] Не менять внешний вид и принятую логику Hero → Kado → Cases без отдельного решения.
- [ ] Не ухудшать стабильные 60 fps на реальных мобильных устройствах.
- [ ] Не включать `Lenis syncTouch`; мобильный touch-scroll остаётся нативным.
- [ ] Не ломать текущую модель слоёв, Page Canvas, iris-переходы и сохранение Android WebGL-буфера.
- [ ] Не жертвовать мобильным гироскопом и виброоткликом ради отложенной загрузки: разрешение/повторное подключение датчиков остаётся внутри явного пользовательского нажатия, а готовность подтверждается реальным сенсорным событием.
- [ ] Сохранять `prefers-reduced-motion`, остановку анимации в скрытой вкладке и вне viewport.
- [ ] Не загружать декоративный эффект раньше ресурса, который нужен для первого понятного кадра.
- [ ] После каждого крупного шага выполнять production-сборку.
