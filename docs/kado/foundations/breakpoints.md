# Брейкпоинты

Kado использует **шесть контрольных ширин**. Это не «включился media и прыгнул layout», а **точки таблицы токенов**, между которыми идёт гладкая интерполяция.

## Таблица

| Имя | Ширина | Роль |
| --- | ---: | --- |
| Mobile | **390** | iPhone-канон (Safari) |
| Tablet | **768** | смена раскладки |
| Desktop | **1280** | основной desktop-макет |
| Wide | **1440** | «домашний» desktop; якорь margin/gutter **40** |
| Ultra | **1920** | мягкий продолжающийся рост |
| 4K-ish | **2560** | потолок шкалы |

Источник: `design-tokens/responsive.json` → `viewports`.

## Как думать

1. На **390 / 768 / 1280 / 1440 / 1920 / 2560** значения токенов **ровно** из таблицы (и кратны 8 / 4).
2. Между ними — линейный `clamp()` (см. [Fluid](./fluid.md)).
3. Композицию (колонки, скрытие nav) можно менять на классических CSS breakpoints; **размеры** при этом всё равно едут по fluid-кривой.

## Почему не 4 точки

Раньше шкала обрывалась на 1440. На практике после Wide нужен **мягкий доезд** до 1920 и потолок у 2560 — без жёсткой полки и без бесконечного зума текста на 4K.

## Stress-test (не контрольные точки)

Проверять глазами, но **не** заводить отдельные токены: 360, 375, 430, landscape, 1536.
